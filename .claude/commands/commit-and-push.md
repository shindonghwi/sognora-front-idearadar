# /commit-and-push

Performs code review and, if there are no issues, commits and pushes to the **development branch**.

> **Project Type**: Idea Generator (Claude AI Agent Configuration)
> **Note**: Only run this command on development branch. Use `/deploy-main` for main branch deployment.

---

## ⛔ MANDATORY: Code Review Required

**YOU MUST RUN code-reviewer BEFORE ANY COMMIT.**

This is NOT optional. Skipping code-reviewer is FORBIDDEN.

```
❌ WRONG: git add . → git commit → git push (SKIPPING REVIEW)
✅ RIGHT: code-reviewer → APPROVED → git commit → git push
```

**If you skip code-reviewer, you are violating the workflow.**

---

## Steps

### 1. Run Code Review

**⛔ YOU MUST USE Task TOOL TO INVOKE code-reviewer AGENT.**

```
Task(
  subagent_type: "sognora-service:code-reviewer",
  prompt: "Review all current changes for commit. This is an AI agent configuration project with markdown and JSON files.",
  description: "Run code-reviewer for commit"
)
```

**DO NOT manually run validation and skip the agent. The agent does comprehensive checks:**

code-reviewer checks for this project:
- **Markdown Syntax**: Valid markdown formatting in agent/command files
- **JSON Validity**: Valid JSON syntax in settings.json and other config files
- **Security Issues**: No API keys, credentials, or sensitive data exposed
- **Agent Definitions**: Complete and well-structured agent specifications
- **Command Definitions**: Clear command workflows and instructions
- **File Structure**: Proper organization in `.claude/agents/` and `.claude/commands/`
- **Documentation Quality**: Clear, comprehensive specifications
- **Naming Conventions**: Consistent file and section naming

### 2. Process Review Results

#### ✅ Status: APPROVED

→ Proceed to **Section 3 (Create Commit)**

#### ❌ Status: NEEDS_CHANGES

**Create GitHub Issue → Auto-fix → Re-validate:**

**Step 1: Create GitHub Issues**

Create an issue for each Critical Issue:

```bash
gh issue create \
  --title "[Critical] {issue title}" \
  --body "$(cat <<'EOF'
## 🔴 Critical Issue

**Category**: {category}

### 📍 Location
- **File**: `{file path}`
- **Line**: {line number}

### ❌ Issue
```markdown
{problem code}
```

### ✅ Fix
```markdown
{fix code}
```

### 💥 Impact
{impact description}

---
🤖 Auto-generated by code-reviewer agent
EOF
)" \
  --label "bug,critical" \
  --assignee @me
```

After creation, output:
```
✅ GitHub Issues created!

🔴 Issue #123: {issue title}
   🔗 https://github.com/{org}/{repo}/issues/123
```

---

**Step 2: Run Auto-fix**

Fix each Critical Issue sequentially:

```typescript
// Example: Read file
Read("{file path}")

// Example: Replace problem code → fix code
Edit({
  file_path: "{file path}",
  old_string: "{problem code}",
  new_string: "{fix code}"
})
```

After fixing all Critical Issues:
```
✅ Auto-fix complete: {N} Critical Issues resolved
```

---

**Step 3: Re-validate (Max 3 attempts)**

Re-run code-reviewer after fixes:

- ✅ APPROVED → Move to Step 4 (commit)
- ❌ NEEDS_CHANGES → Return to Step 2 to fix again (max 3 times)

```
Attempt 1: 3 Critical → fix → re-validate → 1 remaining
Attempt 2: 1 Critical → fix → re-validate → 0 (APPROVED)
→ Proceed to commit
```

**If exceeding 3 attempts:**
```
⚠️ Auto-fix failed (exceeded 3 attempts)

Remaining Critical Issues:
- Issue #124: {problem description}

Manual review required.
```
→ Abort workflow

---

**Step 4: Commit (Include Issue Numbers)**

Include `Fixes #issue_number` in commit message:

```bash
git add .
git commit -m "$(cat <<'EOF'
fix: {fix summary}

{detailed description}

Fixes #123, #124

🤖 Generated with [Claude Code](https://claude.com/claude-code)

Co-Authored-By: Claude <noreply@anthropic.com>
EOF
)"
```

---

### 3. Create Commit (When APPROVED)

Run the following bash commands **in parallel**:
```bash
git status
git diff
git log -5 --oneline
```

Analyze changes and write commit message:
- Identify nature of changes (feat, fix, refactor, docs, style, etc.)
- Focus on "why"
- Keep it concise in 1-2 sentences

**Execute commit**:
```bash
git add .
git commit -m "$(cat <<'EOF'
{commit message}

🤖 Generated with [Claude Code](https://claude.com/claude-code)

Co-Authored-By: Claude <noreply@anthropic.com>
EOF
)"
```

**Important**:
- Always use HEREDOC (`$(cat <<'EOF' ... EOF)`)
- Include Co-Authored-By
- Never commit secret files (.env.local, .env, etc.)

### 4. Handle Pre-commit Hook Failure

If commit fails at pre-commit hook and files are modified:

1. **Check Authorship**:
   ```bash
   git log -1 --format='%an %ae'
   ```

2. **Check Push Status**:
   ```bash
   git status
   ```
   Verify "Your branch is ahead"

3. **Amend if both conditions met**:
   ```bash
   git add .
   git commit --amend --no-edit
   ```

4. **Create new commit if conditions not met**

### 5. Push

```bash
git push origin $(git branch --show-current)
```

**Note**:
- Never force push to main/master branch
- Report to user if push fails

### 6. Completion Message

```
✅ Commit and push complete!

📦 Commit: {hash}
🌿 Branch: {current branch}
📝 Message: {first line of commit message}

🔗 https://github.com/{org}/{repo}/commit/{hash}
```

## Important Rules

### ⛔ CRITICAL - DO NOT SKIP

1. 🚫 **NEVER skip code-reviewer** - This is MANDATORY, not optional
2. 🚫 **NEVER commit without APPROVED status** - No exceptions

### Standard Rules

3. ✅ **Only commit when validation passes**
4. 🔄 **When validation fails** Create Issue → Auto-fix → Re-validate (max 3 times)
5. ⚠️ **Abort if exceeding 3 attempts** (manual review required)
6. ⚠️ **Never commit secret files** (.env, .env.local, API keys, etc.)
7. 📝 **Commit message should explain "why" of changes**
8. 🔄 **Amend pre-commit hook modifications**
9. 🔗 **Include Fixes #issue_number in fix commits** (auto-closes issues)

## Commit Message Convention

- `feat`: Add new agent, command, or feature
- `fix`: Bug fix in agent/command definitions
- `refactor`: Restructure agent/command specifications
- `docs`: Documentation update (README, SPEC files)
- `chore`: Configuration changes, cleanup
